### ⚠️ The local test gate was red — for an environmental reason, not a regression

Re-running the gates after the Vercel correction, `vitest` reported **4 files and 23 tests failing** on a
tree whose only modifications were `.md` files. The failing files were **byte-identical to `HEAD`**
(`git hash-object <file>` == `git rev-parse HEAD:<file>`), and CI was green — so this was not a regression
and not mine.

**The split was clean:** every failing file used `vi.mock`; the only mock-heavy file that passed used
`vi.spyOn`. A 3-line probe settled it — `vi.mock('./lib/utils', …)` followed by `import { sentinel }`
yielded `undefined`, so **`vi.mock` is not hoisted here at all**.

**Root cause.** `process.cwd()` returns a **lowercase drive letter** (`c:\…`) in this shell, and Vitest
derives its `root` from that string. The module paths that follow then differ in case from the ones the
runner uses, and Node caches modules by path *string* — so two `vitest` instances load. Measured: with the
lowercase cwd the banner reads `RUN v4.1.11 c:/Users/…` and 23 tests fail; with an absolute `--root` it
reads `RUN v4.1.11 C:/Users/…` and **all 223 tests pass**. A *relative* `--root .` does **not** fix it —
it resolves against the lowercase cwd. Ruled out by measurement: CRLF (probe was pure LF), the transform
cache, the config loader (`.ts` vs an equivalent `.mjs`), the pool (four modes, isolate on and off), a
second `node_modules` above the repo, and the esbuild platform binary.

**The first fix was wrong, and has been reverted.** `vitest.config.ts` was changed to
`root: fs.realpathSync.native(__dirname)` and the gate went green — but that proved nothing. At the time
`node_modules` had been installed by **bun**, and Bun *symlinks* its packages, so realpath canonicalisation
was happening anyway. Against an npm-installed tree the change is a no-op.
`git diff origin/main -- vitest.config.ts` is now empty.

**The real fix is in `docs/agentic/scripts/verify.sh`** — it re-enters the repo root through `pwd -W`
before any gate runs, so the drive letter is canonical. Red was observed first (15 files failed,
*"no tests"*, **GATES FAILED (2)**, exit 1, plus the false *"a DROP means a guard was deleted"*); after the
fix the same conditions give `tsc` 0 errors, **223 tests / 15 files**, *"All gates green"*, exit 0.
→ **T44** (MITIGATED — the casing sensitivity itself is upstream and unfixed).

**The reported residual did not reproduce once the tree was reinstalled with npm.** *"`npm test` fails on
Windows: all 15 suites, 'Vitest failed to find the current suite'"* was recorded while `node_modules` was
**bun-installed** — a configuration this repo does not support (**T46**). Re-measured 2026-10-06 on a
fresh `npm ci` tree (`node_modules/.bin` holds 28 extension-less shims + 28 `.cmd` and **0** `.exe`):
`npm test` → **223 passed / 15 files, exit 0**. The earlier attribution to npm's shim was wrong and has
been struck.

> ⚠️ **Not re-verified this session:** the lowercase-cwd red state could not be reproduced a second time —
> spawning `node` out of a `process.chdir('c:/…')` harness returns **`EBUSY`** in this sandbox. The
> mitigation therefore stands on the earlier measurement, not on a fresh re-run.
