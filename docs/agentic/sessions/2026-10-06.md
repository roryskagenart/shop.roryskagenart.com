### ⚠️ The GitHub repository had been renamed — found at push time

`git push` returned `remote: This repository moved. Please use the new location:
https://github.com/roryskagenart/shop.roryskagenart.com.git`.

**Verified, not inferred:** `gh api repos/roryskagenart/shop.roryskagen.com --jq .full_name` →
`roryskagenart/shop.roryskagenart.com`. The GitHub repo now **matches the local folder name and the custom
domain** — the opposite of the rule this project was built on ("the remote is `.com`, not `.art.com`;
never infer it from the folder name").

**`/AGENTS.md` §2 was already correct** — an earlier session had updated it, and it warns that
`git remote -v` is stale and untrusted. **The stale artefacts were everywhere else:**
`stack/environments.md`, `plugins/registry.md`, `protocols/preflight.md`, `scripts/preflight.sh`, the
`plans/README.md` blob link, and this session's own project memory. All corrected.

**The local `origin` URL was deliberately not changed.** GitHub redirects renamed repos, so it still works,
and rule 4 makes repointing the remote a human decision. **T23 → MITIGATED**, with the generalisable lesson
recorded: this mapping has already changed once, so **re-verify it rather than pattern-match it**.
